1. 整体流水线

原始用户 trace │ ▼ [阶段 0] 数据预处理 + Rationale 合成 │ ▼ [阶段 1] SFT 冷启（token-level CE）─────┐ │ │ 冻结 checkpoint，用作 ▼ │ RL 初始化 + KL 参考 π_ref [阶段 2] GRPO RL 精调 ◄─────────────────┘ │ reward = w(a) · R_action + R_format ▼ [阶段 3] 评测 + 错误分析 + Reward/数据回流 │ └── 迭代（Phase 2 ~ 3 循环 2~3 轮即收敛）
核心取向：SFT 打底（拿群体分布），RL 上分（啃难例）。不要跳过任一阶段——纯 RL 冷启在论文中只有 24.72%，SFT 直接到 35.14%，SFT+RL 拉到 39.58%。

2. 算法链路的 6 件核心事情

1

构造可学习的 schema（把准确率变成可验证事件）

  • 动作空间定长化：每个 action type 明确必需属性（如 click.element_name、input.element_name + text）。没有 schema 就没有 reward。
  • 强制输出 rationale → action JSON：rationale 提供软 CoT，action 提供硬校验锚点。
  • Fine-grained 子类提前定义（如 click 的 13 个子类），供 reward 加权 + Fine-grained Acc 评测复用。

为什么重要：NextAct 是"属性全中才算对"的严口径，schema 不干净 reward 就是噪声。

2

数据准备 + Rationale Augmentation

  • 缺失 rationale 用 claude-3.5-sonnet / GPT-4o 条件 "HTML + 真实 action" 合成（论文同款做法）。
  • 长 HTML 动态截断：最近几步保留完整 HTML，早期只留 action + rationale，压到 65k tokens。
  • 难例/稀有动作上采样：input / purchase / terminate 专门加权，对抗 86% click 主导的类别不平衡。
3

SFT 冷启（群体层拟合）

  • Loss：token-level Cross-Entropy；Backbone：Qwen2.5-7B-Instruct-1M（论文实测 3B 会崩 Outcome F1）。
  • 配置：AdamW, lr=1e-5, warmup=150, steps=2000, bs=64。
  • 目的：为 RL 提供一个合理起点策略 + 一个可信的 π_ref。
4

Reward 设计（决定 RL 学不学得动的关键）

R = w(â) · Raction  +  Rformat
  • Raction：action type + 所有必需属性完全一致才得 1；否则 0。
  • Rformat：JSON schema 校验通过才得 1。
  • w(â) 难度加权（对抗长尾最有效的招）：
动作权重
正确 input（稀有 + 信息密集）2000
正确大多数 click 子类1000
正确 click: product_option10
正确 click: review / search（最高频）1
正确 terminate1
错误 click（SFT+RL 阶段）−1
错误 click（纯 RL 阶段）0（负号会失稳）
5

GRPO RL 精调（从 SFT checkpoint 起跑）

J(θ) = E[ (1/G) Σᵢ (1/|oᵢ|) Σₜ min(rᵢ,ₜ · Ãᵢ, clip(rᵢ,ₜ, 1−ε, 1+ε) · Ãᵢ) − β · DKL(πθ ‖ πref) ]
  • 每个 prompt 采样 n 个 rollout，组内计算相对优势 Ãᵢ，无需 value network。
  • 训练：VERL + Megatron，tensor parallel + context parallel + activation checkpoint。
  • 参数：2 epochs, bs=64, 8×8 A100；KL 系数 β 建议 0.01 ~ 0.05（太小跑偏，太大退化回 SFT）。
6

迭代回流（每轮必做）

错误切片：按 action 细粒度子类 + 按用户 archetype 切出"低于均值"的 bucket。

原因归类 → 对应修法：

错误类型修法
格式错加重 R_format 的罚项；或在 SFT 阶段增加 schema 对齐样本
Action type 误分类SFT 语料 class-balanced 重采样
属性错（element_name 错位）HTML 表示增强：加 DOM 结构特征 / 外部 selector
稀有动作不敢出继续拉大对应 w(â) 权重

下一轮：先 SFT 吸收新样本（或只 replay 错例），再 GRPO 精调；2~3 轮即收敛。

3. 推荐训练顺序

Phase 目标 预期指标 产出
P0 预处理schema + rationale 合成 + 数据切分—训练/验证 jsonl
P1 SFT v1学好主流分布NextAct ≥ 35%ckpt_sft_v1
P2 GRPO v1难例上分NextAct ≥ 39%ckpt_rl_v1
P3 错误分析找 Top-5 失分桶—错例集 + reward/数据调整方案
P4 SFT v2在错例上继续拟合NextAct 微涨ckpt_sft_v2
P5 GRPO v2难度权重 + β 微调NextAct ≥ 41%ckpt_rl_v2
P6 冻结评测全量 benchmarkFinal提交模型

4. 评测口径（一次性装到位）

  1. NextAct Acc（主指标，exact match）
  2. Action Type Macro-F1（类别平衡性）
  3. Fine-grained Type Acc（子类细度）
  4. Session Outcome F1（全局意图：是否下单 / 终止）
  5. Format Valid Rate（诊断指标，应稳定 > 99%）
  6. Per-user Acc 分布 + Persona-swap rate（1w persona 场景必加，防群体化坍缩）
务必 Day 1 就装好评测 harness。指标如果是后补的，调参时就会只盯 NextAct 做 overfit，Macro-F1 / Outcome 会悄悄掉。

5. 三条最容易踩坑的经验

坑 1：不要跳过 SFT。 纯 RL 冷启 reward 稀疏到训不动；Customer-R1 自己也给了反例（24.72% vs 39.58%）。
坑 2：不要让所有正确动作等权奖励。 会立刻退化成"一直点评论/搜索"。一定要用难度加权把稀有动作（input）抬到 2000，高频动作（click review/search）压到 1。
坑 3：负奖励只在 SFT+RL 阶段加。 纯 RL 阶段加负号会震荡；先 SFT 稳住策略，再放负号惩罚错误 click。
